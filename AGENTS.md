# Pinident agent guide

Start with [docs/PROJECT_SPEC.md](docs/PROJECT_SPEC.md) for the current product/data contract and [docs/IMPLEMENTATION_GUIDE.md](docs/IMPLEMENTATION_GUIDE.md) for module ownership, threading, storage, and verification. [README.md](README.md) is the operator guide. Keep all three documents and the folder-specific agent guides aligned when behavior changes.

## Purpose and current scope

Pinident aims to identify Pinny Arcade pins in bulk, starting with a Windows tool for annotating pins across video frames. The repository now contains reviewed-crop storage, a working OpenCV pin/non-pin rectangle classifier, and a Cloudflare-oriented mobile web companion. Future goals include a reproducible evaluated dataset and model, reliable specific-pin identification across images or video, external collection synchronization, and possibly a native Android workflow. Treat these future goals as goals, not existing features.

This repository is currently a Python wxPython/OpenCV prototype with a TypeScript mobile web companion. `displayvideo.py` opens a video or still-image chooser. `videoscrubber.py` reads video frames or a one-frame image source; `scrubberframe.py` coordinates navigation, annotation, and JSON persistence; `pin_detection.py` proposes candidate boxes and conservatively associates nearby frames. `trained_detection_model.py` trains the working saved pin/non-pin rectangle classifier from reviewed crops and stored Pinpanion stock images; `OpenCVBoxTrainer.py` is a disconnected experimental wrapper. `cloud_sync.py` links desktop reviews/model versions with the Cloudflare Worker implemented in `mobile_web/worker.ts`. `mobile_web/` builds an installable web app with on-device candidate detection, tracking, and collection storage. `mobile_scan.py` and `mobile_server.py` remain a legacy Python service unused by the web app. `controls/` renders and edits Windows boxes, and `events/` defines wx events. `imagescrubber.py` and `displayframe.py` are separate image-viewing prototypes. The development Worker at `https://id.dev.pinpanion.com/` passed UI-only deployment and HTTPS/API checks on 2026-10-05; production remains undeployed. Recheck after changes rather than inferring live status from configuration.

`frame_processing.py` runs playback, GUI button detection, and manual navigation detection on one worker. It receives snapshots of annotation boxes and feedback vectors, reads from a worker-only video capture, and returns results for `ScrubberFrame` to commit on the wx thread. The GUI commit must also update existing `inherited` boxes whose identity was still unverified; otherwise playback discards an adjacent verified identity even though the worker linked it. Keep those boxes inherited, and do not create a second direct feedback example. Next and Previous button clicks must update the visible frame index immediately; either direction can analyze an unchecked frame on the worker using the frame just left as its tracking reference. Rapid navigation invalidates older worker results. Saved-chain reconciliation on manual navigation also uses this worker, a box snapshot, and cancellation/revision checks before committing to the original box objects. Do not access wx widgets, the UI video capture, or the SQLite feedback connection from the worker. Pausing invalidates outstanding results. Play uses a one-shot timer and submits the next frame only after the last result is displayed; do not put the saved-chain reconciliation loop back into each playback result callback. `VideoScrubber` caches repeated frames and reads adjacent frames sequentially; keep the UI and worker capture states separate.

`FrameCache` now shares 128 MiB of decoded, unrotated RGB frames between UI and worker reads, evicting least-recently-used frames. `VideoScrubber` prefetches up to four following frames on a third capture owned by a background thread. Keep the three capture states separate, and stop prefetch on close. A cache hit does not advance a capture cursor. After a relaxed fallback, catalog-match only the newly added boxes; the primary pass already matched existing boxes.

User-edited automatic rectangles carry an optional `bounds_adjustment` relative to their detector proposal and set `bounds_direct`; manual rectangles start with authored bounds. Persist both fields through JSON and undo/redo. Adjacent tracking applies the correction to a new proposal or to an unreviewed saved automatic target after a strong match. A propagated adjustment leaves `bounds_direct` false so later source edits or undo can update it. Preserve the original target object and any separately edited, manual, or directly reviewed target bounds. Propagated geometry is not a new direct training review.

Playback tracking may locally fit foreground pixels around a proposal or missed proposal, expanding edge fragments and tightening stale broad rectangles only after strong appearance/texture agreement with the previous frame. Bound the fitted component relative to the seed so random texture cannot fill a frame. Scale user crop margins as the detector size changes. Saved unreviewed automatic boxes may receive the new geometry, but direct edits, manual boxes, and directly reviewed boxes keep their own bounds. Commit worker geometry to the original box object on the wx thread.

`ScrubberFrame._submit_frame_job` logs UI snapshot/queue time as `ui submit`. The `worker_total` value logged later by `_complete_play_job` is `process_frame` runtime, and the worker log splits it into decode, detection, tracking, catalog, and fallback costs. `PinMatcher` uses a 12-table LSH index with zero multi-probe expansion for large catalogs; keep geometric verification and test transformed-image retrieval when changing its parameters.

Stored review crops carry versioned descriptors. Large feedback stores load their ranker on a separate connection after the window shows, with progress in the status bar; the first legacy upgrade still decodes crops. The feedback database uses WAL mode, and the background upgrade must finish decoding each bounded batch before opening its short write transaction so review clicks remain writable. A changed UI feedback connection makes the worker reload before installation. Playback batches proposal comparisons against those descriptors and consolidates only its changed destination frame; other frame mutations still need full reconciliation. Its one-shot timer subtracts processing and UI commit time from the source frame interval instead of adding a fixed delay after each result.

## Before changing code

- Write strongly typed Python and TypeScript. Give function boundaries and data structures precise types; validate external JSON before treating it as an application type. Do not add `typing.Any`, TypeScript `any` or `unknown`, or type-warning suppressions. Replace existing weak types with concrete types when working in that code.
- Run the checks that apply to changed code. Fix TypeScript compiler and ESLint diagnostics, and Python Pylance diagnostics, at their cause instead of hiding them. Do not leave lint or type warnings in touched code. Run the existing project test suites before reporting completion.

- Read the relevant modules and tests, and check `git status --short` before editing. Preserve user data and unrelated changes.
- Confirm the intended behavior from code or a user decision when an operation could alter annotation data. Do not infer a finished architecture from prototype names.
- Use small, reviewable changes. When a feature crosses GUI, annotation data, and persistence boundaries, define the data behavior first and test it independently of wx where possible.
- Do not introduce a framework, remote service, model, scraper, Android stack, or new on-disk schema merely to prepare for future work. Record alternatives for planning when the choice is still open.

## Annotation and data invariants

- **Training → Review saved areas...** opens the desktop classifier review dialog over rectangles already in the loaded annotation file. Show all non-rejected areas first in frame and box order; show hidden **Not a pin** reviews only after no non-rejected area remains. If a review rejects a later queued box, move that box behind the remaining non-rejected work. It shows the source crop alone, saved presence/identity state, and the highest eligible catalog appearance match with a match-strength score. Review actions use the existing owner history and feedback paths: confirm pin presence or a specific catalog identity, reject a suggested identity while directly confirming pin presence, mark an automatic area not a pin, or correct one rejected automatic observation back to a positive pin crop. **Confirm identity**, Y, and **Confirm selected catalog pin** use an explicitly selected catalog result or a search narrowed to one catalog pin; with no selection or search, only Confirm identity/Y confirm the saved suggestion. An ambiguous search requires a result selection. Do not advance when the owner refuses the chosen identity. N rejects the saved identity; advance immediately after applying a review in memory. Coalesce idle JSON saves on a worker using independent box snapshots, and commit reviewed feedback crops with a worker-owned SQLite connection. Refresh the UI feedback model after each committed batch. File → Save and normal close must wait for older background writes before writing newer state. Navigation without a review does not create a training label. Do not run detection to create new boxes while merely browsing this mode, and never replace a rejected ID with that same suggestion.

- Suppress a new desktop detection candidate when it mostly overlaps another box (more than half of the smaller box, or IoU at least 0.35); slight overlap is valid. When tracking or catalog identification establishes that mostly overlapping boxes represent the same pin, consolidate saved frames to one box per pin per frame. Preserve the winning box object, rectangle, and direct review; remove duplicate direct and linked feedback. Do not discard conflicting directly verified identities, deliberate manual names, or wrong-identity reviews merely because rectangles overlap. Edit-triggered merges belong to the originating undo entry.

- A successful **Run training now** installs its classifier in the live desktop feedback model immediately. Cancel detector jobs submitted with an older model snapshot before installing; subsequent Detect Pins, navigation, and Play jobs use the updated model in the same process. A cloud model refresh must not replace a current local classifier.

- Training continuation starts from the saved linear classifier when current feedback and stock-image inputs only add examples. Saved per-example fingerprints distinguish additions from edits or removals. Rehearse retained examples from other media during each incremental update; an unchanged run keeps the weights, while corrections and deletions require a full fit from current stored crops so stale labels cannot linger. Keep the feedback DB, model file, and adjacent metadata together for cross-machine continuation. The pin/non-pin classifier remains separate from specific-pin identity matching.

- `BoxData.coords` is an `(x, y, width, height)` tuple. Check image bounds and positive width/height at boundaries; distinguish source-image coordinates from scaled or rotated display coordinates.
- Frame annotations are currently saved as JSON beside the selected video (`<video-stem>.json`). JSON maps frame indices to lists of boxes with `coords`, `tags`, `source`, and optional `prev_box_id`. Existing files may omit `source` and `prev_box_id`; preserve compatibility when changing readers or writers.
- `BoxData.id` comes from Python object identity, so `prev_box_id` is a legacy, non-durable link. New annotations carry a UUID `track_id` across matched frames; the JSON reader generates one for legacy boxes that lack it. Preserve this field on save/load and do not assume old links can be reconstructed.
- `BoxData.review_state` is `unconfirmed`, `inherited`, `confirmed`, or internal `rejected`. Direct pin-presence confirmation without a verified identity appears orange; directly presence-confirmed boxes with a verified identity appear green. Linked observations on the same associated track are also orange. After **Not this pin** or **none of these**, a presence-confirmed box stays orange until its specific identity is verified again. Blue is reserved for unidentified, unconfirmed candidates; red is a provisional specific identity on an unconfirmed candidate. `identity_confirmed` separately marks a specific name/ID as authoritative; pin-presence confirmation alone must not set it. A newly drawn manual box starts as a directly confirmed pin with a blank editable name and a positive feedback crop; `unknown-#` placeholders cannot be confirmed as identities. **Remove area** deletes only the current annotation and never creates a negative example. **Not a pin** on an automatic area retains a hidden `rejected` observation in the JSON sidecar, creates one direct negative example, and suppresses automatic observations on that track and visually matching unreviewed adjacent boxes; a prior positive review on the same automatic track is withdrawn. Preserve manual annotations and separately confirmed tracks during visual reconciliation. Both context menu and label-row actions must update the frame owner's box list before persistence. The image and tag panels must exclude rejected boxes from interaction while retaining them in the frame list for matching. Catalog matching may improve a provisional automatic suggestion or identify a directly presence-confirmed automatic box; it skips verified identities, rejected boxes, and manually entered names; inherited presence-only tracks can still receive provisional suggestions.
- `feedback_id` and `feedback_label` on a box mark a direct user decision. Confirmation is positive; explicit **Not a pin** on an automatic area is negative. Keep rejected observations in the frame JSON with their coordinates, original suggested tags/`pin_id`/score, and track ID; hide them through `review_state`, not deletion or clearing their provenance. A negative crop has no true pin identity in the feedback database, even if the rejected box retains a false catalog suggestion. Each saved inherited frame on a directly confirmed pin track contributes one distinct positive crop during training indexing; propagated rejections remain non-duplicate negatives. Linked crops do not set direct feedback fields. **Remove area** is not a non-pin label; it removes that observation and its prior positive example if present. `detection_feedback.py` keeps reviewed RGB crops and provenance in the ignored local SQLite database, and its conservative nearest-neighbour ranker filters/ranks new detector proposals. Undo/redo and annotation load must keep the database in sync. Do not claim neural training or measured accuracy from this feedback baseline.
- **Not this pin** rejects a specific identity while preserving the box and its pin-presence review. `identity_rejections` stores immutable direct reviews with ID/name, original rectangle, and frame; the feedback database stores the corresponding wrong-identity crop separately from pin/non-pin examples. Exclude reviewed IDs/names from catalog matches on that tracked object, clear the visible wrong suggestion, and retry catalog matching. Copy exclusions when tracking to a new frame; never count propagated copies as independent training crops. Undo, redo, and JSON load must synchronize these reviews. The local nearest-neighbour identity baseline also uses wrong-ID crops to veto visually similar identity suggestions; it is not a neural classifier.
- **Training → Feedback model...** and the frame status bar show stored versus usable positive/negative crops and feedback revision. `FeedbackModel.refresh` rebuilds vectors immediately before saved-area review mode; after that mode starts, review, undo, and redo feedback refreshes after staged batches commit on the save worker. `reload` handles annotation import. Worker jobs receive a stable snapshot with that revision. Preserve the distinction between saved crops and usable descriptors. Per-detection feedback logs include proposal, suppression, and unscored counts. Suppression requires a strong reviewed-negative match that exceeds the best positive match; the saved binary SVM only changes ordering. This keeps stock-artwork domain shift from hiding real video pins.
- Frame-level user assertions live in `_frame_presence` in the existing annotation JSON. `frame_presence.py` derives checkbox states from those assertions and marked pins: confirmed, inherited, catalog-identified, or explicitly named boxes count; blue proposals and rejected boxes do not. **Contains pin** asserts at least one, **Contains set** at least two. Checking when the marked count is short starts worker detection and a relaxed contrast-normalized fallback. Keep an unmet user assertion checked so a missed pin remains visible. Removing the last marked pin clears the assertions; undo/redo restores them with box changes.
- An explicit **Detect Pins** run and manual navigation to an unprocessed frame use the relaxed search if the primary pass leaves no visible candidates, even without a frame-presence assertion. Explicit Detect Pins also runs best-effort catalog suggestions on existing unverified candidates and pin-presence-confirmed boxes; it compares confirmed/inherited unidentified crops with the reviewed-identity model as well. Commit scores and IDs to original boxes while preserving directly confirmed identities. On frame changes, retry unresolved confirmed/inherited pin areas before ordinary automatic candidates, even if the frame was previously scanned; keep the scan on the worker. Playback runs a bounded relaxed search for up to six new near-edge candidates when adjacent frames change meaningfully, even if a tracked pin is already visible; static frames do not trigger it. This limits speculative backing-card proposals. A manually revisited empty frame that Play processed gets one full pass. The status bar reports primary/fallback counts. Keep the fallback on the worker and keep its outputs as review candidates, never confirmed pins. Its contour-fill and local-contrast checks suppress repeating tabletop texture while retaining a low-contrast filled pin shape; do not let a saved SVM hard-veto them.
- Explicit **Detect Pins** logs `PINIDENT_DETECTION` records under one run ID: source-frame proposal rectangles, source/display/panel geometry, and each committed box's source and panel rectangle plus provisional identity. Keep diagnostics confined to explicit runs so Play logs remain manageable. Use the source-versus-panel coordinates to distinguish detector proposals from display offsets when triaging clustered rectangles.
- The web scanner emits a `PINIDENT_DETECTION web` browser-console JSON record for forced paused/photo scans and throttled crowded live scans. It includes original source size, bounded scan proposals, model rejections, final boxes, and overlay CSS coordinates; a local reference index can add provisional suggested pin IDs/names and match strengths, while direct `pin_id`/`name` remain empty until user tagging.
- Saved unconfirmed boxes can be reconciled with identified, confirmed, or rejected observations through contiguous adjacent-frame chains when both overlap and appearance are strong. Previous and Next navigation pass the frame just left as an explicit adjacent reference, even when the destination was processed before. A strong local template match may add a tracked observation to an empty saved frame or replace a mostly overlapping unreviewed automatic candidate that fails visual matching; keep it inherited or unconfirmed according to the source, never directly confirmed. Manual navigation checks on the worker; playback only matches the adjacent frame in its worker to keep wx responsive. Cancel an obsolete scan on navigation, editing, or Play; never decode the chain with the UI capture. Preserve the existing target box object and any separately edited or directly reviewed coordinates. An unreviewed automatic target may inherit strongly matched user-corrected bounds. A confirmed identity may replace a provisional catalog `pin_id`; a user-entered name can inherit that identity only when the names match, while a blank manual box may accept it after strong visual matching. Rejection may merge separate unconfirmed automatic tracks and hide their observations in both directions, but must not overwrite manual or confirmed tracks. Propagated rejections are not additional negative feedback examples. Include asynchronously reconciled rejection changes in the originating removal's undo entry. Propagate identity to blank boxes on the same track, but do not mark them directly confirmed without a user action.
- A pin partly outside any video edge can have a narrow clipped box. An adjacent detector proposal or saved box may be much larger as more of the pin becomes visible. Match its visible fragment against a subregion of the larger box only with strong texture/colour agreement and nearby position; do not require ordinary IoU or equal box size in that case. Keep every frame's rectangle within that frame's image bounds, preserve separately edited or reviewed saved target coordinates, carry corrected bounds into unreviewed automatic targets, and allow newly tracked rectangles to expand. If detection misses, local template search may expand a near-edge fragment through foreground refinement when the matched fragment lies inside the larger component. Distinct-looking edge objects must not inherit the pin ID. The coarse proposal stage admits narrow components touching an image edge, with an exterior-background contrast check.
- Filter only *new untracked automatic* candidates by a within-frame size reference. Prefer the median width and height of directly presence-confirmed, fully visible, non-set pins, regardless of specific identity. If none are visible, use fully visible inherited pin-presence observations. Without either reviewed source, use the median of a tight group only when at least three fully visible, non-rejected observations agree in size and form a strict majority. Require each full dimension to be 50%–150% of its reference. Even without a majority, three distinct, fully visible, non-rejected peers more than twice as wide and high as an untracked automatic candidate rule out that tiny proposal. Apply both rules to primary and relaxed proposals after tracking, before adding boxes. Existing annotations and tracked observations survive proposal filtering, but a saved unconfirmed automatic box that meets the tiny-peer rule loses only its provisional catalog suggestion on ordinary matching; keep its rectangle and direct reviews. A clipped candidate may be narrower only along its clipped axis. Keep the small-corner-fragment guard. Physical millimetres do not imply pixels without camera scale. The worker logs the count it filters.
- An orange `inherited` box is backed by a confirmed pin-presence observation on its track. Treat its identity as authoritative for subsequent adjacent matches only when `identity_confirmed` is true; presence-only confirmation may link tracks but must leave conflicting provisional names unresolved. Never overwrite a direct user-confirmed identity or label. Skip matching only when the box already inherited a verified identity; an inherited presence-only box still needs an identity scan. Automatic unconfirmed detections use the conservative ORB matcher; confirmed/inherited presence boxes try strong catalog and reviewed-crop identity matches first, then show the highest ranked eligible catalog identity as a provisional suggestion when those checks abstain. Exclude identities rejected on that box or track. If no eligible identity reference exists, leave it unnamed. `match_confidence` is match strength, not a calibrated probability; retain it through unconfirmed tracking, clear it with `identity_confirmed` when the user edits the name, and include both fields in save/load and undo history.
- Desktop catalog suggestions prefer geometrically verified ORB matches. When geometry is inconclusive, compare stock-image colour and coarse spatial layout across quarter turns; assign a provisional name to ordinary unconfirmed areas only when the visual score, both component scores, and the lead over a distinct pin clear conservative thresholds. Confirmed/inherited pin-presence areas and areas with a direct wrong-identity review show the strongest eligible ranked match even below those thresholds. Exclude every reviewed wrong ID/name so **Not this pin** advances to a different suggestion when one exists. The interactive replacement list uses the same ranking for manual selection. A fresh ordinary unconfirmed-area scan that abstains clears an older unverified catalog name, ID, and score after the reviewed-crop identity check; preserve directly verified identities and wrong-identity reviews.
- When appearance tracking misses an adjacent box, a strong independent catalog suggestion for the same identity plus substantial box overlap can inherit a verified identity. Require a directly confirmed or trusted inherited source, an automatic unconfirmed target, a catalog score of at least 0.60, and IoU of at least 0.55. Leave distant matches, conflicting IDs, presence-only confirmations, and user-labelled targets alone. Use this after catalog matching on worker jobs and on saved adjacent frames; the resulting orange state is inherited, not a new direct user confirmation.
- A direct pin-presence confirmation can inherit a specific identity only after an adjacent saved-box visual match to a verified identity. Mark that result with `identity_inferred`; it remains green for presence, but it is not an independent identity authority. Recompute it from a direct verified source after changes and persist the flag through JSON and undo history. The right-pane editable catalog picker writes both the canonical pin name and stable `pin_id`; free text clears the ID and match score.
- A user may directly confirm the same tracked pin in several adjacent frames. Each direct review stays green and keeps its own feedback crop; linking tracks must preserve all direct presence and identity decisions. Confirming an inherited box in the current frame promotes only that observation to direct confirmation. Visual matching may join independently confirmed adjacent observations when their verified identities agree; conflicting direct pin IDs stay separate.
- **Add to training data** compares direct positive/negative and wrong-identity reviews plus each saved inherited pin frame with stored metadata by stable example ID. Newly drawn unnamed manual boxes are direct positive pin examples even when their identity is unknown; count them among indexed pin crops and among crops without a verified ID. Each distinct rejected catalog ID in a **none of these** page is one wrong-identity example; propagated copies with the same review ID count once. Decode and save only new or changed crops; delete absent source examples, and refresh the local proposal and identity exemplar model for affected IDs. An unchanged session should not decode frames or bump the model revision. Frame reads run on the worker with progress and ETA callbacks; SQLite and wx updates stay on the UI thread. Report wrong-identity counts separately from pin/non-pin counts. This updates a conservative nearest-neighbour baseline, not a neural model.
- **Run training now** first completes that indexing step, then fits or continues the linear classifier in `trained_detection_model.py` using all usable indexed positive and negative feedback crops plus every usable Pinpanion stock image in the catalog SQLite database as a positive example. The classifier and its JSON metadata are saved beside the database as `<database-stem>.svm.yml` and `<database-stem>.svm.yml.json`, then loaded on startup even when the review digest or catalog state has changed (a warning and Settings show that it is stale until retrained). `FeedbackModel.filter_and_rank` uses the saved classifier only to downrank predicted non-pin proposals; reviewed negative exemplars can still suppress strong matches. A binary model prediction alone must not erase a plausible rectangle, because stock artwork and video crops differ. The heuristic still has to propose the rectangle. Train on a worker using a snapshot of feedback crop bytes and a separate worker-owned catalog connection, never the UI SQLite connection. Install the model on the wx thread only if both the feedback digest and catalog state remain current. Model metadata stores stock pin IDs, original Pinpanion names as explicit per-image tags, source URLs, rights, total/usable counts, and a combined training digest; stock images do not become feedback rows. At least one usable positive image or crop and one reviewed negative crop are required. Settings shows both paths and whether the active classifier matches current reviews and catalog. Do not claim measured accuracy, identity classification, full-image detection, or neural training from this SVM.
- A newly trained classifier uses version 2 portable RGB features. With a configured desktop sync token, `Run training now` first imports new shared web crops and publishes the resulting linear decision weights to the authenticated Worker model endpoint only when stock-image rights are verified; current Pinpanion imports have unverified source terms, so their trained model stays local. `export_mobile_model.py` still writes ignored `mobile_web/model.json` as a static fallback. The browser validates version and shape, caches the model after a successful fetch, checks for updates periodically, and filters only new proposals. Older version 1 desktop files may still load locally but must be retrained before mobile export. Check rights status before distributing model weights derived from reviewed crops.
- Undo and redo history belongs to `ScrubberFrame` and is keyed by frame index. `annotation_history.py` stores object references plus only changed locations and fields; never restore a deep-copied panel box list. ImagePanel gestures and label edits notify the frame owner before and after mutation. Confirmations and rejections can affect boxes on other frames, so their history entry must include those changes. Restoring an entry must refresh both image and tag panels while preserving unrelated box identities and metadata.
- Multi-selection belongs to `ImagePanel` and is UI state, not serialized annotation data. Bulk confirm, remove, and not-a-pin actions must update the current frame's actual box list in one owner transaction and one undo entry; feedback is synchronized for every directly changed box. Preserve the earlier rule that only automatic boxes can receive a not-a-pin negative review. Keep selected boxes highlighted until removed or hidden, and prune the selection on frame changes.
- Keep raw media, extracted frames, and generated labels out of commits unless a small fixture is intentionally added. The local `images/` and `labels/` directories contain ignored data; do not modify or clear them as part of routine work.
- For future artwork imports, record source, identifier, rights/usage status, and provenance. A public image URL alone does not establish a reusable training asset.

## Testing and verification

- The desktop entry point installs an unhandled-exception hook before creating wx. It writes full GUI-callback and thread tracebacks to the rotating `%LOCALAPPDATA%\Pinident\pinident.log` file and the configured console logger. Preserve traceback logging in catches for unexpected errors; GUI tests fail when an uncaught wx callback exception occurs. Use the logged traceback to fix the underlying error rather than treating an error dialog or a passing test summary as sufficient diagnosis.

- Use the project `.venv` when present. At the initial scan (2026-10-02), it has Python 3.13, wxPython, OpenCV, NumPy, PyYAML, and pytest. `requirements.txt` lists runtime dependencies but does not currently list pytest.
- Current verification command: `.\.venv\Scripts\python.exe -m pytest -q`. Detection tests live in `tests/test_pin_detection.py`; the existing GUI tag removal test is repaired, and `pytest.ini` registers the `gui` marker.
- Add focused tests as code changes are made. Prefer synthetic NumPy frames, in-memory JSON streams, and temporary files for data, geometry, tracking, and persistence tests. Use wx integration tests for event wiring and visible interaction behavior; give each test its own clean GUI state and destroy windows.
- For a bug fix, add a regression test that fails for the observed behavior before changing it when practical. For a new feature, cover the data path and at least one representative integration path. Avoid tests that only restate implementation details or require the ignored local media.
- Verify affected tests and report the exact command and outcome. GUI smoke checks should state whether they were actually run; a passing unit test does not establish GUI behavior.
- wx size events may fire before the frame slider exists during construction; do not render a frame from `on_resize` until the source frame and required controls are ready. An unavailable Cloudflare endpoint is an expected startup network state: show unavailable status and a concise warning, while retaining full tracebacks for unexpected sync errors.
- Desktop close keeps a progress dialog visible through worker completion, atomic annotation save, and reader release. Keep its per-step and overall percentages and time estimates updated without blocking the wx event loop. Do not destroy the frame before the save succeeds; active requested training must commit on the wx thread before the worker barriers complete.

## Known prototype boundaries

- Detection is a two-stage OpenCV heuristic followed by an optional trained OpenCV pin/non-pin rectangle classifier and a conservative nearest-neighbour feedback ranker, not a trained neural pin detector. Real backing-card artwork can create false proposals and hide real pins. `Detect Pins` adds review candidates; adjacent-frame association and local template search copy tags only for strong matches. Play submits one frame at a time to the worker. The label list refreshes on pause. Explicit GUI detection and Next buttons use the worker; direct `on_next` calls retain the synchronous path for existing integrations. Console logs time decode, detection, tracking, catalog, bitmap, labels, and reconciliation. There is no recovery after long occlusions or scene cuts.
- `ScrubberFrame.find_object_in_next_frame` is legacy ORB code and is not used by the new navigation path. `OpenCVBoxTrainer` remains disconnected and incomplete; the working crop-level pin/non-pin SVM trainer is `trained_detection_model.py`. This is not a full-image neural detector or a measured identity model.
- `pin_catalog.py` stores reference images with provenance in SQLite. `pinpanion_sync.py` imports unseen IDs and their images from the public Pinpanion `pins.json` feed at startup in a background thread. It also stores event names for year/show match labels and refreshes the matcher when event names change. Its stock-image iterator selects imported source images, excluding extra local references, and takes each image tag from the original feed record name even if the local catalog display name later changes; training uses these images as binary positive examples while the ORB matcher still handles specific identities. The current ORB/FLANN feature index is rebuilt after import and only assigns a `pin_id` for strong geometric matches; accuracy on real pins has not been measured. Source rights are recorded as unverified.
- Saved-frame catalog scans run on the existing worker after adjacent-frame reconciliation, so a tracked identity gets priority and the UI can continue painting. A result commits only if the box and catalog index are still current. The displayed percentage is ORB geometric inlier consistency for a provisional match, not a calibrated probability.
- `mobile_web/` is an Android-accessible web app, not a native APK. It proposes and tracks candidate areas on-device, including large close-up silhouettes while suppressing contained detail proposals, stores collection records in browser local storage, and caches the public Pinpanion catalog metadata in IndexedDB after an online fetch. Its service worker caches the app shell for offline launches. Direct reviewed crops and saved frame annotations with bounded image content upload automatically to a versioned Cloudflare D1 training event log; the desktop pulls them with `PINIDENT_SYNC_TOKEN`, extracts positive crops only from confirmed/inherited annotation boxes, trains the pin/non-pin classifier locally, and publishes a versioned web decision plane through the Worker. Each saved frame is a distinct training opportunity. A separate web **Unknown** difficulty mark stores the crop locally but uploads only its 36-value visual signature to D1; similar future crops sort behind clearer candidates for this and other users, without becoming pin/non-pin training examples. The browser refreshes that model while open. Collections stay local. A new local-only browser reference matcher can provisionally suggest pin names at 50% visual match strength, with the strongest candidate setting a size prior; the Python ORB matcher has not been ported and real-footage accuracy is unmeasured. The required catalog-derived reference index is not deployed while its source-image rights remain unverified. There is no authenticated Pinpanion collection synchronization or neural recognition model. Do not guess Pinpanion write endpoints or credentials from the public catalog feed.
- Web annotation selection is transient: tapping a visible box toggles it, and the default paused-frame drag selects boxes when it covers strictly more than half of each box, otherwise draws a new area. Explicit Select areas and Draw area tools override that choice. The photo/video element must be contained in the aspect-aware stage; `stage_geometry.ts` maps the same fitted frame for box rendering and pointer drags so portrait images remain taggable to their bottom edge. Delete removes selected boxes from the current frame without a non-pin review. Saving an edited paused frame reuses its annotation ID so the desktop can remove stale crops for deleted boxes after cloud sync. Web **OK — Save and finish** commits the bounded frame and boxes locally before stopping/resetting the scan, then queues cloud sync; a failed save must leave the scan open.
- Web pin pickers show the five most recently chosen catalog IDs first when no search text is entered, then a divider and remaining pins. The list is unique, local to the browser, and shared by frame tagging, training corrections, and library additions; typed search uses the ordinary filtered catalog.

## Working style for future agents

- Keep user-facing plans tied to observable milestones: annotation reliability and portability, dataset export and provenance, model evaluation, then mobile/collection integration as separately chosen work.
- State assumptions, unresolved product decisions, tests run, and remaining risks in the handoff. Update this guide when the architecture or commands materially change.
- Add a reusable skill only after a repeatable project workflow exists (for example, annotation-fixture generation or model evaluation) and its steps can be verified. Keep the skill narrower than this repository-wide guide.
