# GUI controls guidance

This folder contains wxPython panels used by `scrubberframe.py`. Read the parent `AGENTS.md` first, then [../docs/PROJECT_SPEC.md](../docs/PROJECT_SPEC.md) for the current action/data contract and [../docs/IMPLEMENTATION_GUIDE.md](../docs/IMPLEMENTATION_GUIDE.md) for owner and worker boundaries.

- Type panel callbacks, box data, and owner interfaces precisely. Do not use `typing.Any` or suppress Pylance warnings; resolve diagnostics at their cause and run the relevant Python checks.

- Follow an annotation edit from input event to `BoxData`, frame ownership in `ScrubberFrame`, repaint, and JSON save/load. A panel-only change can appear correct while leaving the saved frame unchanged.
- Keep image coordinates separate from widget coordinates. `ImagePanel` scales images and supports rotation; exercise clicks, drags, resize, and box selection at more than one display size when changing geometry.
- Explicit Detect Pins diagnostics log each final box's unrotated source rectangle and `_box_panel_rect` result, plus panel size, bitmap size, centering offset, and rotation. Preserve this mapping when changing box drawing or resize behavior.
- Resize geometry lives in `boxgeometry.py`; store box coordinates in unrotated source-image pixels. Hover hit testing uses panel pixels, and dragging converts the displayed rectangle back to source coordinates.
- When an automatic box is moved or resized, update its `bounds_adjustment` by the change in source-image `(x, y, width, height)`, set `bounds_direct`, and change `coords`. Manual boxes already have user-authored geometry. Undo/redo and JSON must keep these values so adjacent tracking can carry a corrected crop and distinguish a separate destination edit.
- `ImagePanel.selected_boxes` is the visible multi-selection; `selected_box` remains the most recently selected box for the single-box tag editor. Ctrl-click toggles an individual box. A drag starting on empty image space selects only visible boxes when the marquee covers more than 50% of each existing box's displayed area; touching or covering exactly half still creates a new manual box if no other box crosses the threshold. That new box is a directly confirmed pin-presence review; the owner records one positive feedback crop and starts best-effort catalog matching after the gesture's history entry commits. Right-click on any selected box preserves the group. Bulk context actions go through `ScrubberFrame` once, creating one history entry and synchronizing all affected feedback examples. Commit pending right-pane text edits before building a context menu. Offer **Confirm selected identities** whenever any selected box has a specific identity still needing direct verification, including groups with already verified or unnamed boxes; verify only eligible named boxes and leave already verified identities and unnamed boxes unchanged. A mixed selection also offers **Confirm selected as pins** for pin-presence review, which must preserve current labels. **Not a pin** in a mixed selection applies only to automatic boxes.
- The frame owns one `EVT_CHAR_HOOK` handler. When no text field has focus, Del removes the visible selection without negative feedback, N marks selected automatic boxes as not pins, X rejects the current identity of exactly one selected named box, and Y directly confirms that selected pin identity. Context menu items show Del or the underlined N/X/Y mnemonic. Ctrl+X and typing inside the catalog text field must retain normal text behavior. Left-clicking a rectangle scrolls its right-pane label editor into view and focuses the editor panel so shortcuts work immediately; clicking the name field focuses text entry for typing.
- Events are defined in `events/` and connected across `ImagePanel`, `TagPanel`, and `BoxTagPanelEdit`. Check both event type and the receiving widget when editing handlers. Prefer testing observable emitted events or data changes over private widget attribute names.
- Reproduce GUI defects with a small wx test or a documented manual sequence. Ensure test-created frames and timers are cleaned up so subsequent tests are independent.
- The bottom frame-number marker panel uses measured text widths and adapts its interval to available width. Keep labels inside the panel with spacing between them, and recalculate when the panel resizes.
- Unidentified, unconfirmed candidates display blue. Unconfirmed candidates with a suggested identity display red. A directly presence-confirmed pin without a verified identity displays orange, as does a linked observation on a confirmed track. A directly presence-confirmed box with a verified identity displays green, including one whose identity was strongly inferred from an adjacent verified frame. After **Not this pin** or **none of these**, a presence-confirmed box remains orange, including when another identity is suggested; confirming the new identity restores green. Confirmed and inherited pin-presence areas receive the highest ranked eligible catalog suggestion when stronger identity checks abstain, provided an unrejected reference is available.
- Catalog suggestions whose identity is not confirmed show their optional match-strength percentage before the name so it stays visible in narrow boxes. A question mark distinguishes a suggested name on a green or orange pin-presence-confirmed box. This percentage is a feature-match consistency score, not a calibrated probability.
- Hovering a visible box shows the complete box-label text, including its match score, in a wrapped native tooltip. Clear the tooltip when the pointer leaves, a gesture starts, or the displayed frame/box list changes; rejected boxes never expose a hover label.
- The single-box context menu shows **Confirm is a pin** only for boxes without a specific identity; it sets only the presence review state and is disabled when that direct review already exists. **Confirm pin identity** requires a specific non-placeholder name or catalog ID and sets `identity_confirmed`. Named boxes offer **Not this pin** to retain wrong-identity feedback, clear the suggested name, and retry catalog matching. If strong matching abstains, the retry uses the next highest ranked catalog identity outside all reviewed exclusions, even when the area's pin presence is unconfirmed. Keep that targeted retry pending through a catalog matcher refresh. Report when no catalog images or reviewed identities are loaded, or when no eligible identity remains. Automatic areas also have distinct **Remove area** (ordinary deletion) and **Not a pin** (negative review) actions. Keep **Not a pin** bottommost in both single-box and multi-selection context menus. The right-pane tick confirms presence in the current frame, its **Confirm identity** button directly verifies the selected name in that frame, and its bin performs ordinary deletion. When an inherited box already has a verified identity, label the button **Verify here (optional)** so users know a second direct review is not required. Keep a blank text row for newly drawn boxes and lay out the added panel immediately.
- **Attempt detection** is available from a visible box's context menu, including when several boxes are selected (it targets the clicked box). It scans only that box's source-image crop on the worker against catalog and reviewed identity examples, then attaches an undoable provisional match to the original box if it is still current. On an explicit retry, prefer a strong reviewed-identity match over a weak catalog appearance match, but retain a geometric catalog match. If both checks abstain, clear an older unverified suggestion in the same undoable action and report it in the status bar. Preserve directly verified identities and typed names, and discard results after navigation or edits. Report when the best match is unchanged or no identity sources are loaded so a completed attempt is distinguishable from an unresponsive action.
- The label panel may reuse a widget when adjacent boxes have the same position and name. Rebind it to the current frame's `BoxData` object before refreshing; keeping the previous frame's object gives stale confirmation status and sends edits to the wrong frame.
- When catalog reference images exist, the single-box context menu offers **Replace with pin** with up to 10 unique, scored appearance matches for the source-image crop. Include the current suggested ID on the first page even when it falls outside the appearance top ten, so rejecting the page excludes the visible suggestion. Show available year and show metadata between the score and name, such as `99% [2021/West] Some pin`; omit missing metadata. Choosing one is a direct user identity confirmation, with one positive crop and one undo step; if it replaces a different named identity, retain a wrong-identity review of that old value in the same step. **none of these** below a separator records one direct wrong-identity review per listed ID for that rectangle, retains pin-presence state, retries identity matching for the selected rectangle while excluding those IDs, and reopens the next ranked page. Attach any new match as a provisional suggestion. Those reviews share source provenance but are distinct exclusions; duplicate names must not exclude unrelated IDs. Rank from precomputed appearance vectors to keep menu construction responsive. The displayed score is similarity, not a calibrated probability.
- Use `wx.TextCtrl.ChangeValue` when repainting a label from `BoxData`. `SetValue` emits `EVT_TEXT`; the delayed edit handler then clears the confirmed catalog ID despite no user edit. Only actual text edits should clear `pin_id` and `match_confidence`.
- The catalog picker uses a `wx.TextCtrl` and a separate results popup. A native `wx.ComboBox` overwrote the user's query when its choices changed during typing, and loading the full catalog into each combo cost hundreds of milliseconds per box. Debounce the popup search for 240 ms, search the full catalog by substring of name or ID, and show at most 75 matches. Opening the arrow must filter by the field's current value and return focus to the text field so typing can continue. Preserve an uncommitted text draft across catalog-option and panel refreshes. During a mouse click into the popup, focus can briefly be absent; defer focus-based dismissal and keep the popup visible while the pointer is inside it. Refresh an open popup when `set_tag` changes a committed value. Display IDs only for duplicate names, but retain the ID in the mapping used for selection. Keep the picker and its arrow within the tag pane at an 800-pixel window width.
- wx controls must be created on the GUI thread. Freeze the tag pane while adding or removing many rows, lay it out once, and skip unchanged row repaints. The aggregate `tag panels` log separates change detection, existing-row updates, native control creation, and final layout time; slow picker `SetItems` calls also log their item count and duration.
- Rejected automatic detections remain in frame data as hidden observations. Image hit testing, painting, and the label list omit them; detection and tracking still read them to avoid proposing the same object again. A new user-drawn box is a correction and should take priority over a matching rejection.
- The owner `ScrubberFrame` records undo and redo transactions. Call its begin/end callbacks around a gesture or label edit; do not keep whole-frame deep-copy snapshots inside a panel. Removal and confirmation must continue through owner callbacks so the saved frame and any linked-frame state are included in history.
- Owner callbacks also update detection feedback. A direct confirmation records a positive example; **Not a pin** on an automatic area records a negative example. **Remove area**, the right-pane bin, and Remove Selected never create a non-pin example. Keep these decisions in the owner rather than panel-specific handlers.
- **File → Save** writes the current annotation JSON and frame-presence assertions without closing the window. Flush pending debounced label edits through the existing owner history callbacks before writing; unchanged displayed labels must not become catalog selections. Feedback and catalog SQLite writes already commit separately.
- **Confirm all suggestions** is a bottom-row button below the main button bar. It directly verifies only visible boxes on the current frame with a real catalog `pin_id`, excluding rejected, unidentified, placeholder, and already directly verified boxes. An inherited box with an identity is promoted to a direct green review in this frame. Keep all resulting box changes and feedback crops in one owner undo entry; leave blue candidates and name-only manual edits alone.
- **Training → Add to training data** indexes changed review crops and refreshes the in-memory exemplar ranker. Its completion status in the right pane lists pin crops, pin crops without a verified ID, non-pin crops, and wrong-ID reviews; newly drawn manual pin crops may show zero added now because they were saved when drawn. **Training → Run training now** completes that indexing step and fits the saved OpenCV pin/non-pin classifier on a worker, including unnamed positive pin crops and usable Pinpanion stock images read from the catalog database. Keep both menu items disabled while either job runs, and report insufficient usable pin or non-pin crops without creating a model file.
- Keep File → Save, Settings, and Load Annotations... and Training → Feedback model..., Add to training data, and Run training now in their menus rather than duplicating them in the button bar. File → Settings displays active paths/status and does not edit a separate settings file. The button bar retains frame controls and Detect Pins; **Confirm all suggestions** remains in its bottom row.
