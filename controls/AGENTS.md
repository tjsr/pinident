# GUI controls guidance

This folder contains wxPython panels used by `scrubberframe.py`. Read the parent `AGENTS.md` first.

- Follow an annotation edit from input event to `BoxData`, frame ownership in `ScrubberFrame`, repaint, and JSON save/load. A panel-only change can appear correct while leaving the saved frame unchanged.
- Keep image coordinates separate from widget coordinates. `ImagePanel` scales images and supports rotation; exercise clicks, drags, resize, and box selection at more than one display size when changing geometry.
- Resize geometry lives in `boxgeometry.py`; store box coordinates in unrotated source-image pixels. Hover hit testing uses panel pixels, and dragging converts the displayed rectangle back to source coordinates.
- `ImagePanel.selected_boxes` is the visible multi-selection; `selected_box` remains the most recently selected box for the single-box tag editor. Ctrl-click toggles an individual box. A drag starting on empty image space selects only visible boxes when the marquee covers more than 50% of each existing box's displayed area; touching or covering exactly half still creates a new manual box if no other box crosses the threshold. That new box is a directly confirmed pin-presence review; the owner records one positive feedback crop and starts best-effort catalog matching after the gesture's history entry commits. Right-click on any selected box preserves the group. Bulk context actions go through `ScrubberFrame` once, creating one history entry and synchronizing all affected feedback examples. **Not a pin** in a mixed selection applies only to automatic boxes.
- The frame owns one `EVT_CHAR_HOOK` handler. When no text field has focus, Del removes the visible selection without negative feedback, N marks selected automatic boxes as not pins, and X rejects the current identity of exactly one selected named box while keeping its pin-presence review. Context menu items with those shortcuts show Del or an underlined N/X mnemonic. Ctrl+X and editing inside the catalog text field must retain normal text behavior. Image clicks set focus back to the image panel so the shortcuts work after tagging.
- Events are defined in `events/` and connected across `ImagePanel`, `TagPanel`, and `BoxTagPanelEdit`. Check both event type and the receiving widget when editing handlers. Prefer testing observable emitted events or data changes over private widget attribute names.
- Reproduce GUI defects with a small wx test or a documented manual sequence. Ensure test-created frames and timers are cleaned up so subsequent tests are independent.
- Unidentified candidates display blue. Identified detections awaiting review display red. A user-confirmed box displays green; the same confidently tracked pin in other frames displays orange. A confirmed unidentified pin retains its confirmation colour and may receive a scored catalog suggestion when its name is blank.
- Catalog suggestions whose identity is not confirmed show their optional match-strength percentage before the name so it stays visible in narrow boxes. A question mark distinguishes a suggested name on a green or orange pin-presence-confirmed box. This percentage is a feature-match consistency score, not a calibrated probability.
- Hovering a visible box shows the complete box-label text, including its match score, in a wrapped native tooltip. Clear the tooltip when the pointer leaves, a gesture starts, or the displayed frame/box list changes; rejected boxes never expose a hover label.
- The context menu has separate **Confirm is a pin** and **Confirm pin identity** actions. The first sets only the presence review state; the second requires a specific non-placeholder name or catalog ID and sets `identity_confirmed`. Named boxes offer **Not this pin** to retain wrong-identity feedback, clear the suggested name, and retry catalog matching. Automatic areas also have distinct **Remove area** (ordinary deletion) and **Not a pin** (negative review) actions. The right-pane tick confirms presence in the current frame, its **Confirm identity** button directly verifies the selected name in that frame, and its bin performs ordinary deletion. When an inherited box already has a verified identity, label the button **Verify here (optional)** so users know a second direct review is not required. Keep a blank text row for newly drawn boxes and lay out the added panel immediately.
- The label panel may reuse a widget when adjacent boxes have the same position and name. Rebind it to the current frame's `BoxData` object before refreshing; keeping the previous frame's object gives stale confirmation status and sends edits to the wrong frame.
- When catalog reference images exist, the single-box context menu offers **Replace with pin** with up to 20 unique, scored appearance matches for the source-image crop. Choosing one is a direct user identity confirmation, with one positive crop and one undo step; if it replaces a different named identity, retain a wrong-identity review of that old value in the same step. **none of these** below a separator records one direct wrong-identity review per listed ID for that rectangle, retains pin-presence state, and reopens the next ranked page. Those reviews share source provenance but are distinct exclusions; duplicate names must not exclude unrelated IDs. Rank from precomputed appearance vectors to keep menu construction responsive. The displayed score is similarity, not a calibrated probability.
- Use `wx.TextCtrl.ChangeValue` when repainting a label from `BoxData`. `SetValue` emits `EVT_TEXT`; the delayed edit handler then clears the confirmed catalog ID despite no user edit. Only actual text edits should clear `pin_id` and `match_confidence`.
- The catalog picker uses a `wx.TextCtrl` and a separate results popup. A native `wx.ComboBox` overwrote the user's query when its choices changed during typing, and loading the full catalog into each combo cost hundreds of milliseconds per box. Debounce the popup search for 240 ms, search the full catalog by substring of name or ID, and show at most 75 matches. Opening the arrow must filter by the field's current value, including a programmatically populated suggestion; an empty field shows the full limited list. Refresh an open popup when `set_tag` changes that value. Never replace the text field contents while filtering. Display IDs only for duplicate names, but retain the ID in the mapping used for selection. Keep the picker and its arrow within the tag pane at an 800-pixel window width.
- wx controls must be created on the GUI thread. Freeze the tag pane while adding or removing many rows, lay it out once, and skip unchanged row repaints. The aggregate `tag panels` log separates change detection, existing-row updates, native control creation, and final layout time; slow picker `SetItems` calls also log their item count and duration.
- Rejected automatic detections remain in frame data as hidden observations. Image hit testing, painting, and the label list omit them; detection and tracking still read them to avoid proposing the same object again. A new user-drawn box is a correction and should take priority over a matching rejection.
- The owner `ScrubberFrame` records undo and redo transactions. Call its begin/end callbacks around a gesture or label edit; do not keep whole-frame deep-copy snapshots inside a panel. Removal and confirmation must continue through owner callbacks so the saved frame and any linked-frame state are included in history.
- Owner callbacks also update detection feedback. A direct confirmation records a positive example; **Not a pin** on an automatic area records a negative example. **Remove area**, the right-pane bin, and Remove Selected never create a non-pin example. Keep these decisions in the owner rather than panel-specific handlers.
