## Data ownership and threading

`pin_detection.add_unique_boxes` rejects new detector proposals with substantial overlap against an existing area. `consolidate_overlapping_boxes` resolves saved duplicates after tracking or identity changes: more than half of the smaller rectangle must overlap (or IoU must reach 0.35), and the same pin identity or an unreviewed automatic duplicate must be established. `ScrubberFrame` applies consolidation on the wx thread across saved frames, keeps the winning `BoxData` object and coordinates, removes duplicate direct and linked feedback, and includes edit-triggered removals in undo history. Keep conflicting verified identities, manual names, and wrong-ID reviews when identity is uncertain.

The web **OK — Save and finish** action uses `saveCurrentFrame` and `scan_session.ts` to await local IndexedDB persistence before `stopSource` clears the source, boxes, and result cards. A failed save or superseded scan cannot reset the current source. Remote D1 upload remains a queued retry. Record the snapshot's video time when scanning, so finishing a running video saves time metadata for the same pixels and boxes.

`app.ts` keeps Pause and OK in the top source-action row. While a camera or recorded video runs, `scanControls` hides the four source choices and candidate actions, showing Pause and OK once a bounded frame is ready. Pause scans the current frame and opens the annotation tools while retaining the video source for Resume. OK uses the existing save-before-reset flow, then releases media tracks. Source choices return after the source is stopped; a photo opens directly in still-frame review.

The web scanner admits near-frame-size connected areas and removes contained detail proposals before tracking. Its synthetic scanner tests cover a close-up silhouette and an isolated smaller object; real-camera quality remains unmeasured.

`ScrubberFrame` owns the per-frame `BoxData` objects, frame-presence assertions, undo/redo entries, and persistence. GUI controls must notify that owner before and after mutations, including bulk actions, so actual frame lists and review rows stay synchronized. `ImagePanel` selection is transient UI state, not JSON. Preserve source-image coordinates and the original `BoxData` object when committing async results. `track_id` is the durable link; never rely on `BoxData.id` or legacy `prev_box_id` after reload.

One frame-processing worker reads its own video capture and immutable snapshots of boxes, catalog data, and feedback vectors. It never touches wx widgets, the UI capture, or the UI SQLite connection. The wx thread commits worker results only when frame index, box identity, and cancellation/revision checks still match. Rapid navigation, editing, and pause invalidate stale work. Next/Previous display the destination frame immediately, then process it with the frame just left as the adjacent reference. Playback submits the next frame only after the prior result is displayed. Cloud HTTP work also runs off the wx thread; UI/SQLite commit stays on the UI thread. Training runs from a snapshot of crop bytes, not the UI database connection, and installs only while the feedback digest is current.

`FrameCache` shares decoded, unrotated RGB frames across UI and processing reads, with a 128 MiB byte limit and least-recently-used eviction. `VideoScrubber` starts a daemon prefetch thread after UI display; it uses its own capture and keeps up to four following frames ready. The latest display position supersedes old prefetch requests. Stop the prefetch thread on window close. A cache hit does not advance either capture's cursor, so the next cache miss may need to seek. In `process_frame`, the relaxed fallback's catalog pass only examines newly added boxes because the primary pass already checked the others.

`ImagePanel` records an automatic box's user geometry change in `bounds_adjustment` alongside `coords` and sets `bounds_direct`. Manual boxes start with an authored-bounds marker. `associate_frame_boxes` carries that adjustment onto matched detector proposals; an unreviewed saved destination may receive the corrected rectangle while retaining its original `BoxData` object. A propagated adjustment leaves `bounds_direct` false, so a revised source correction or undo updates the destination from its reconstructed detector bounds. Do not overwrite a separately edited, manual, or directly reviewed destination. Both worker result commit and saved-frame reconciliation must copy an eligible corrected rectangle onto the original object. Keep both geometry fields in JSON, annotation history, and duplicate-box copies. Legacy records without them remain detector-owned.

Tracking locally refits a detector proposal against the current frame before association when overlap and appearance support it. This handles a narrow edge proposal that remains narrow as the object enters, or a stale broad proposal when the object shrinks. A missed proposal may use the same fit after local template search. Limit the fit's area relative to its seed and require a strong visual match to the previous observation; random texture must not expand into a frame-sized rectangle. Saved unreviewed automatic targets can receive the fit, while direct edits and reviews keep their bounds. Scale user adjustment margins with the new detector dimensions; when no detector baseline exists, retain an authored marker with zero adjustment rather than reusing obsolete pixel offsets. Worker geometry changes must be copied onto the original box on the wx thread during Play and reconciliation.

`filter_new_candidates_by_pin_size` runs after tracking in both primary and relaxed worker passes. It uses only directly confirmed, fully visible, non-set boxes as anchors and compares each new untracked automatic proposal's width and height to 75%–133⅓% of the respective median. Permit a smaller width or height only when that axis touches the frame boundary; keep upper limits and the opposite full-axis lower limit. Do not filter saved annotations or tracked proposals. If no qualifying anchor exists, leave proposals unchanged. The 22–55 mm physical size range is context, not a pixel threshold without camera scale.

wx resize events can arrive while `ScrubberFrame` is still constructing its controls. The resize handler must defer image display until the source frame and slider exist. Startup cloud sync attempts the configured endpoint in the background; HTTP or DNS failures are reported as a concise warning and unavailable status while local annotation and model work continues. Unexpected sync failures still need a traceback for diagnosis.

`controls/markerpanel.py` computes frame-number marks from measured wx text widths and panel width; it repaints on resize. Preserve non-overlapping, unclipped labels and the first/last frame marks when changing the bottom scrubber.

Frame JSON lives beside the selected media as `<media-stem>.json` and is written atomically on File → Save or exit. Direct feedback crops live in ignored `detection_feedback.sqlite3`; catalog data in ignored `known_pins.sqlite3`. The trained classifier lives beside the feedback DB as `<database-stem>.svm.yml` and `<database-stem>.svm.yml.json`; the cloud model cache path is made by replacing the classifier's `.yml` suffix with `.cloud.json` (normally `<database-stem>.svm.cloud.json`). Use File → Settings in the running app for exact active paths and freshness. The Settings dialog is read-only; there is no general editable settings file established by this repository. Do not commit local media, SQLite stores, model weights, secrets, or generated labels.

On close, `ScrubberFrame` vetoes the first close event, shows `ShutdownProgressDialog`, stops new playback/cloud timer work, and polls active worker futures from the dialog's wx timer. Requested training finishes its wx-thread commit before worker queue barriers complete. A dedicated save worker serializes the now-stable frame map and atomically replaces the JSON sidecar, reporting frame-level progress through `wx.CallAfter`. Only then does the processing worker release its capture and the frame destroy. Keep wx and SQLite access on the UI thread; the save worker only reads annotations after editing is disabled. A failed save leaves the window open.

## Change checklists

After training saves and passes digest/catalog checks, invalidate pending detector jobs before installing the model on the wx thread. New `FrameJob` objects must snapshot the updated `FeedbackModel`; no restart is needed. Cloud fetches can update the cached remote version but must not replace a current local trained classifier in this process or at startup.

Training continuation loads the prior saved classifier even when new reviews have made it stale for detection. `TrainedDetectionModel.train` compares saved per-example fingerprints with the current feedback and stock-image inputs. Additions continue the saved linear weights and rehearse all retained examples; no change returns the same model. A changed or removed input, an old manifest-free model, or a feature-version mismatch requires a fresh fit from all current crops. Keep the feedback DB, `.svm.yml`, and `.svm.yml.json` together for continuation across machines. The UI installs a result only if review digest and catalog state still match after the worker finishes.

For an annotation action, trace `ImagePanel`/label event → `ScrubberFrame` transaction → box state → frame list → feedback row → JSON → undo/redo → redraw. A name confirmation differs from pin-presence confirmation. Keep the border colors consistent with those decisions: blue for an unnamed unconfirmed candidate, red for a named unconfirmed candidate, orange for confirmed presence without verified identity or an inherited pin, and green for a directly presence-confirmed box with verified identity. A confirmed orange area already has its positive review, so its presence-confirmation action is disabled. **Not a pin**, **Not this pin**, **none of these**, and **Remove area** have distinct training effects; the table in [PROJECT_SPEC.md](PROJECT_SPEC.md) is the expected contract. A replacement page includes the current catalog suggestion even when it is outside the colour-ranked top ten, so rejecting that page cannot immediately suggest the same excluded ID. Check multi-selection and single selection, current-frame versus adjacent-frame effects, and stale worker cancellation. Favor focused regression tests with synthetic frames and isolated wx windows.

For detection or identity changes, keep confirmed names and manually typed labels authoritative. New proposals can be downranked by the saved classifier and filtered by strong reviewed negatives and the within-frame size prior; existing annotations and tracked observations survive proposal filtering. Explicit detection and manual navigation use the relaxed fallback when needed. The relaxed search checks both contour fill and contrast against nearby pixels to avoid tiny repeating background textures; preserve low-contrast pin coverage and clipped edge fragments. During playback, a meaningful change between adjacent frames also triggers a relaxed search for new candidates near the frame edges, capped at six additions; static frames do not trigger it. A retry must either show a changed provisional suggestion or report why no new result appeared. Identity match percentages are geometric/similarity strengths, not probabilities.

An explicit Detect Pins run passes a diagnostic run ID through `FrameJob`/`FrameResult`. `frame_processing.py` logs the source frame size, primary/relaxed proposals, filtering count, and result count; `ScrubberFrame` logs committed boxes after display mapping with source and panel rectangles plus suggested identity fields. Preserve the source versus panel distinction when changing geometry. Diagnostics are limited to explicit runs so playback does not flood the console. Reproduce a coordinate report with a screenshot or a description of true pin locations because the log contains no pixels.

The browser `scanFrame` can fill optional diagnostics with proposal, model-rejection, below-match-threshold, and size-filtered rectangles without rerunning detection. `app.ts` logs one `PINIDENT_DETECTION web` JSON record after forced scans and throttled crowded live scans, comparing the bounded scan coordinates with CSS overlay coordinates. Keep media pixels and private collection data out of diagnostics. The binary browser model only filters proposed pin/non-pin areas; `identity.ts` separately assigns provisional catalog names and match-strength percentages. The 50% gate and strongest-match size reference apply only to new automatic boxes, so manual and tracked reviewed boxes survive. `build_identity_index.py` creates an ignored local index from catalog images; `npm run dev:local-index` is its local preview path. Keep publication gated on verified artwork rights; normal deploy scripts require a publishable index. Local directly tagged and rejected examples improve matching on that browser without becoming an automatically published model.

For training changes, separate three layers: direct reviewed crops plus per-frame inherited pin views in SQLite, the immediately refreshed exemplar ranker, and the persisted OpenCV SVM fitted by **Run training now**. The SVM also reads every Pinpanion stock image from the catalog SQLite database on the worker, derives one positive feature per usable image, and records its ID, original Pinpanion name as a tag, source URL, and rights status in model metadata. Do not insert those stock images as feedback reviews or claim the binary SVM identifies specific pins. A linked positive view has a stable source/frame/track ID and is indexed only when its track has a direct positive; it must not acquire a direct `feedback_id`. Count unnamed positive pin crops and each distinct rejected catalog ID in a **none of these** page; propagated negative and wrong-ID reviews still count once. **Add to training data** reconciles linked samples after edits, while annotation import preserves unchanged linked crops without redecoding them. If the session is unchanged, avoid media decode and revision bumps. Reject a trained result when reviews or the catalog change during the fit. Hold web publication when stock rights remain unverified. Preserve Python/TypeScript RGB feature parity and portable-model version checks when altering the trained model.

For web sync changes, keep direct reviews and saved frame annotations automatic and idempotent, collections local, and `SYNC_TOKEN` server/desktop only. Web rectangle selection is transient UI state. Delete removes selected boxes from the current frame without a negative review. A later save on that same paused frame reuses the annotation ID and posts a changed event; the desktop removes stale positive crops for deleted boxes. The shared D1 event payload includes the bounded image; desktop import extracts a positive crop for each confirmed/inherited pin box and skips unconfirmed/rejected boxes. Unknown difficulty marks are separate from labeled training events: save the crop locally, sync only its signature through the `difficulty_marks` D1 table, and sort similar candidates later without dropping them. Exclude `/api/*` from the service-worker cache. D1 event revisions are the desktop pull cursor. Model uploads require a base-version check. Treat remote HTTP state as unverified until a real deployment and API smoke check succeed. Do not modify Pinpanion collection endpoints without verified documentation.

For web pin-picker changes, use `catalog.ts` to keep the five most recent known pin IDs in localStorage and partition only the currently eligible catalog results. With empty search text, show Recents before the remaining pins in both the tag dialog and training dropdown. Typed search returns normal matches; stale and local custom IDs cannot become recent known-pin choices. Selection from tagging, training correction, and library actions all updates the same list.

The `ui submit` log measures snapshot creation and queueing in `ScrubberFrame._submit_frame_job`. `worker_total` in the later `ui commit` log measures `process_frame` execution, with its own decode/detect/track/catalog/fallback breakdown. `fallback_detect` and `fallback_catalog` split the extra search and identity lookup inside fallback. The large-catalog `PinMatcher` uses 12 LSH tables with no multi-probe expansion; retain geometric verification and the indexed-catalog transformed-image test if tuning it. A local synthetic benchmark improved with this setting, but it does not establish real-video speed or identity accuracy.

## Local verification

For photo preview changes, test portrait contain-fit placement and a pointer near the bottom of the displayed image. `app.ts` updates the stage aspect ratio after capture, and CSS absolutely contains the media so its intrinsic size cannot expand the grid row beyond the visible stage. `stage_geometry.ts` must remain shared by overlay drawing and pointer mapping.

The paused web overlay defaults to Select or draw. Its drag decision is a pure scanner helper so the same more-than-half selection rule applies before the app chooses between replacing the transient selection and adding a manual rectangle. Explicit Draw area and Select areas modes override the decision.

From the repository root, use the existing virtual environment when available:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

From `mobile_web/`, after `npm ci` if dependencies are absent:

```powershell
npm run typecheck
npm test
```

For GUI work, add a focused wx integration test and run a real GUI smoke check when practical; report separately whether a visible smoke check occurred. Tests use synthetic images and temporary stores, not ignored local media. For Cloudflare work, `npm run dev` is local preview; `npm run deploy:dev` and `npm run deploy:prod` are distinct remote deployments that require credentials, D1 migrations, secrets, and HTTPS checks. The development Worker at `https://id.dev.pinpanion.com/` passed deployment and HTTPS/API checks on 2026-10-04, including the difficulty GET route after migration `0002_difficulty_marks.sql`, frame-annotation sync, rectangle-selection controls, and the recent-pin picker. ## Australian pin portal ownership

`aus_portal/dist/index.html` and `styles.css` own the standalone static portal. `aus_portal/.openai/hosting.json` declares its static output. `aus_portal/generate_qr.py` regenerates the SVG with the repository's OpenCV environment and validates its encoded URL. This portal does not depend on the desktop editor or `mobile_web/`. Keep its destinations and pending-link state aligned with `aus_portal/README.md`; do not guess personal or unconfirmed URLs.

The opening copy is the PAX Aus 2026 welcome and games invitation directly above the card grid. Keep the browser title and Site display title aligned with that copy.
The first two card images are local files under `aus_portal/dist/images/`, sourced from `lionet.au`. Their square crop and text contrast are controlled in `styles.css`; verify both mobile and desktop layouts after image changes.
The Bouquet card's `Info` button opens the native `<dialog>` in `index.html`; keep its instructions aligned with the owner's wording and verify close and focus restoration with keyboard and touch layouts.
The Scavenger Hunt card and the dialog's inline link both target the supplied event board URL; update them together if the board changes.
