# Mobile web companion

Read [../docs/PROJECT_SPEC.md](../docs/PROJECT_SPEC.md) for the shared review/model contract and [../docs/IMPLEMENTATION_GUIDE.md](../docs/IMPLEMENTATION_GUIDE.md) for desktop ownership and verification before changing a cross-boundary behavior.

- All browser code is strongly typed TypeScript. Do not use `any` or `unknown` types or diagnostic suppressions. Validate JSON and browser storage at their boundaries, then work with concrete types. Run `npm run typecheck` and `npm test`; fix TypeScript and ESLint warnings correctly when a lint check is configured. Commit `package-lock.json`, not `node_modules` or `dist`.
- `app.ts` handles camera/photo/video input. `scanner.ts` makes bounded on-device candidate proposals and conservatively tracks reviewed or rejected areas. Large connected silhouettes can occupy most of a close-up frame; keep them as proposals and suppress smaller detail proposals substantially contained within them. Preserve isolated small-object detection. `stage_geometry.ts` supplies the shared contain-fit transform for drawing boxes and mapping pointer drags; keep the media element absolutely contained in the stage and set the stage aspect ratio from the loaded source so portrait photos show their full height. `identity.ts` uses a locally built catalog reference index and browser-local reviewed examples to give provisional names and match-strength percentages. New automatic boxes require at least 50% match strength; the strongest match supplies a 50%–150% width/height reference for other fresh boxes, with a clipped-edge exception. Manual and tracked reviewed boxes bypass the gate. The percentage is not a calibrated probability. Keep frame dimensions bounded and invalidate the previous track when changing sources.
- `scanFrame` fills optional proposal/model-rejection, below-match-threshold, and size-filter diagnostics for the app's `PINIDENT_DETECTION web` browser-console record. Paused/photo scans log once; crowded live scans are throttled. Include original and bounded frame sizes plus overlay CSS geometry so coordinate offsets can be distinguished from bad proposals without logging pixels.
- On a paused frame, taps toggle visible rectangle selection. The default Select or draw tool selects existing boxes covered by strictly more than half their own area and draws a manual box only when none qualify. Select areas always performs selection; Draw area always creates a manual box, including over an existing one. Selection is transient, rejected boxes are not selectable, and Delete area(s) removes annotations rather than teaching a non-pin. Saving edits to the same paused frame must reuse its annotation ID so the desktop importer can withdraw positive crops from deleted boxes. **OK — Save and finish** persists the current bounded frame and all boxes locally, queues cloud sync, then stops the source and clears scan UI; a failed local save keeps the frame open. **Stop without saving** discards current unsaved changes. Keep pending upload bookkeeping from overwriting newer local frame edits.
- `model.ts` implements version 2 RGB features and the exported desktop linear SVM decision plane for pin/non-pin filtering of new proposals. The desktop can publish that decision plane to a versioned D1 model table through an authenticated Worker route after training, when stock-image rights are verified. The binary model may include Pinpanion stock images as positive examples and carries stock counts in its payload; it does not predict a specific pin ID. `export_mobile_model.py` remains a manual static fallback. The browser refreshes the model on launch, return to the app, and periodically. Keep Python/TypeScript feature parity tests and reject unknown model versions. Never infer a specific pin identity from this classifier. An offline cached model may remain available through the service worker; browsers have no upload credentials.
- `build_identity_index.py` reads stored catalog images, provenance, and rights into an ignored local reference index. `npm run dev:local-index` previews it locally. Normal deploy scripts require `identity-index.json` generated with `--publish`, which refuses unverified rights. The current 1,814 Pinpanion stock images are unverified, so this matcher is not deployed. User-tagged positive and rejected negative feature examples stay in that browser's localStorage, capped at 200 of each; they are not a Cloudflare model upload.
- `service-worker.ts` caches the app shell for offline launches. Do not cache camera frames, private libraries, or remote artwork in the service worker. The phone library is in localStorage; catalog metadata is in IndexedDB after its first successful online fetch.
- `reviews.ts` stores direct training classifications, separate Unknown difficulty marks, and saved still-frame annotations in a separate IndexedDB database. Definite reviews and saved frame annotations upload their bounded image data, source/time, and unverified rights status to D1; offline records retry by stable ID on reconnect. Frame annotations include unconfirmed and rejected boxes for provenance, but the desktop importer extracts training crops only from confirmed/inherited pin boxes. Unknown marks persist locally with the crop but upload only a 36-value visual signature; they never enter the desktop training event stream or change a scan box review state. Rank visually similar future crops after clearer candidates using local and recent shared marks, while keeping all candidates available for later review. Collections stay local. The training queue is made from a paused camera/video frame or photo; unreviewed queue items are session-only. A hand-drawn box uses coordinates in the bounded scan image. The provisional catalog matcher can supply `suggested_pin_id` when its index is available; show the suggested-pin answer only when that field is present. Tagging an annotation does not by itself add that pin to the collection.
- `catalog.ts` parses Pinpanion's public `pins.json` fields (`year`, `categoryIds`, `setId`, `paxEventId`, `groupId`) and their named lookup lists. The pin picker filters this cached metadata without sending search terms or media to the Worker. Preserve the legacy ID/name-only IndexedDB snapshot reader when changing this format. Keep known catalog selection prominent and local unknown-pin naming separate.
- Known pin selections in the catalog dialog, training identity correction, and library actions share a localStorage list of the five most recent unique catalog IDs. When the search query is empty, render **Recents** first and then a divider and remaining pins without duplicates; typed search uses normal filtered results. Keep facet filters effective in the catalog dialog and ignore stale IDs absent from the cached catalog. Local unknown-pin IDs do not become catalog recents.
- `library.ts` owns the existing v1 on-device collection format. Items store stable pin IDs and quantities; `pinpanion:<id>` is distinct from a `local:<id>` custom tag. Preserve existing local libraries when evolving this schema, and keep export working.
- `worker.ts` forwards `https://pinpanion.com/pins.json` at `/catalog.json`, accepts same-origin direct training reviews and saved frame annotations in D1, exposes authenticated incremental event reads and version-checked model uploads, and serves the latest model at `/model.json`. It is not used for scanning. The optional Python preview serves the catalog route from the same URL. Do not substitute a hand-maintained valid-pin list for this source. The Worker secret `SYNC_TOKEN` is for the desktop only; never put it in frontend code. There is no verified user-authenticated collection write API.
- The D1 `training_events` table has a server revision cursor; browser review and frame annotation retries use stable IDs. Each annotation event stores the bounded frame image and every box; desktop import makes one positive crop per confirmed pin box and skips unconfirmed/rejected boxes. The separate `difficulty_marks` table stores idempotent visual signatures from same-origin `POST /api/difficulty-marks`; public `GET` returns at most 500 recent signatures without crops. Keep `/api/*` out of the service-worker shell cache. Authorized desktop GET `/api/training-reviews?after=<revision>` is paged, while browser POST to the same route is public and same-origin. Keep pages under the desktop 6 MB response bound. Authorized `PUT /api/model` checks `base_version` and returns 409 on conflict; public `GET /model.json` serves the latest D1 version or static fallback. Keep request validation and image-size bounds, and preserve these contracts with Worker tests. Rate limiting and monitoring remain deployment work before broad public use.
- Browser camera and service workers need a secure origin on Android. Use `npm run dev` for a local Cloudflare preview and `npm run build` for static assets. For browser UI changes, check ordinary and phone-size viewports; do not request camera permission during automated smoke checks.
- While camera or recorded video is scanning, show **Pause to annotate frame** and **OK — Save and finish** in the top row instead of the four source choices. Keep candidate-card and annotation actions hidden until paused. Pause retains the source for Resume; OK saves before stopping it. Return source choices after finishing or stopping.
