# Mobile web companion

- All browser code is strongly typed TypeScript. `npm run typecheck` checks the app, service worker, and Cloudflare Worker; `npm test` builds and checks library and scanner tests. Commit `package-lock.json`, not `node_modules` or `dist`.
- `app.ts` handles camera/photo/video input. `scanner.ts` makes bounded on-device candidate proposals and conservatively tracks reviewed or rejected areas. It does not identify a catalog pin automatically. Keep frame dimensions bounded and invalidate the previous track when changing sources.
- `service-worker.ts` caches the app shell for offline launches. Do not cache camera frames, private libraries, or remote artwork in the service worker. The phone library is in localStorage; catalog metadata is in IndexedDB after its first successful online fetch.
- `catalog.ts` parses Pinpanion's public `pins.json` fields (`year`, `categoryIds`, `setId`, `paxEventId`, `groupId`) and their named lookup lists. The pin picker filters this cached metadata without sending search terms or media to the Worker. Preserve the legacy ID/name-only IndexedDB snapshot reader when changing this format. Keep known catalog selection prominent and local unknown-pin naming separate.
- `library.ts` owns the existing v1 on-device collection format. Items store stable pin IDs and quantities; `pinpanion:<id>` is distinct from a `local:<id>` custom tag. Preserve existing local libraries when evolving this schema, and keep export working.
- `worker.ts` is a Cloudflare Worker route that forwards only `https://pinpanion.com/pins.json` at `/catalog.json`; it is not used for scanning. The optional Python preview serves the same route from the same URL. Do not substitute a hand-maintained valid-pin list for this source. There is no verified user-authenticated collection write API. Do not add speculative sync requests, scrape a user's account, or place credentials in frontend code.
- Browser camera and service workers need a secure origin on Android. Use `npm run dev` for a local Cloudflare preview and `npm run build` for static assets. For browser UI changes, check ordinary and phone-size viewports; do not request camera permission during automated smoke checks.
- Cloudflare Workers Static Assets deployment is split into the production `id.pinpanion.com` Worker and a separate `env.dev` Worker at `id.dev.pinpanion.com`. Deploy with `npm run deploy:dev` and `npm run deploy:prod` respectively. Keep the custom domains on their respective environments; `pinident.pages.dev` would require a distinct Cloudflare Pages project. Do not claim a deployment is live until both the Wrangler publish and HTTPS smoke checks succeed. Browser storage is isolated by hostname.
